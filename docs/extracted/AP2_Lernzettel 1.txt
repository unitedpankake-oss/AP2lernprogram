Über diesen Lernzettel
Dieser Lernzettel ist auf die schriftliche AP2 (Teile 1, 2, 3) für Fachinformatiker Anwendungsentwicklung nach der neuen Verordnung (seit 2020). Er ist datengestützt: Alle alten Prüfungen, Lösungen und Übungssimulationen aus dem Ordner per OCR analysiert (Sommer 2022 – Winter 2025/26) und nach Häufigkeit der Aufgabentypen sortiert. Teil 1 — Planen eines Softwareproduktes
Format: 90 min · 100 Punkte · 4 Aufgaben · meist 20–30 P pro Aufgabe.
Strategie: Schau dir IMMER zuerst alle 4 Aufgaben an. Schreibe Pseudocode/UML zuerst auf Konzeptpapier, dann sauber. Punkte fallen meist genau auf Ergänzungen — Multiplizitäten an Beziehungen, Pfeilrichtungen, Methodensignaturen mit Sichtbarkeit.

1.4 Wirtschaftlichkeit & Make-or-Buy
Wirtschaftlichkeit = Ertrag / Aufwand. Eine Investition lohnt sich, wenn Ertrag > Aufwand bzw. ROI positiv.
ROI = Gewinn / investiertes Kapital × 100 %
Amortisationsdauer = Investition / jährlicher Rückfluss
Kapitalwert (NPV) = Σ abdiskontierter Cashflows − Investition

1.5.2 Anwendungsfalldiagramm (Use-Case)
Elemente: Akteure (Strichmännchen außerhalb), System-Rahmen (Rechteck), Use Cases (Ellipsen), Beziehungen <<include>> (zwingender Teil), <<extend>> (optionale Erweiterung), Vererbung von Akteuren.
Vorgehen:
Aus Anforderungstext alle Verben mit Akteur als Subjekt isolieren („Aktionär kann sich registrieren" → Use-Case “registrieren”).
Akteure links und rechts vom Systemrahmen, außerhalb.
Use-Cases ins Rechteck.
Verbindungen ziehen (Linie ohne Pfeil = Assoziation).
<<include>>/<<extend>> nur wenn explizit genannt.
Faustregel zur Punktezahl: Jeder Akteur, jeder Use-Case und jede Beziehung gibt typischerweise 1 Punkt — also nichts vergessen!
1.5.3 Aktivitätsdiagramm
Zeigt Ablauf mit Start, Aktivitäten, Verzweigungen, Synchronisationen, Ende.
Symbole:
● Startknoten (gefüllter Kreis)
⏹ Aktivität (abgerundetes Rechteck mit Verb)
◆ Verzweigung (Raute mit Bedingung in eckigen Klammern [ja]/[nein])
▬ Synchronisationsbalken (Fork/Join — parallel auseinander/zusammen)
⏺ Endknoten (Ring um Punkt)
Swimlanes (Spalten) trennen Akteure/Systemkomponenten.
Tipp: Verben in Aktivitäten verwenden („Daten erfassen“, „Mail versenden”). Nach jeder Verzweigung müssen die Pfade wieder zusammenführen oder enden.
1.5.4 Sequenzdiagramm
Zeigt zeitlichen Ablauf zwischen Objekten.
Lifelines: vertikale gestrichelte Linien unter Objektnamen :Klasse oder name:Klasse.
Aktivierungsbalken = Objekt arbeitet gerade.
Pfeile: durchgezogen + ausgefüllte Spitze = synchroner Aufruf; durchgezogen + offene Spitze = asynchron; gestrichelt = Rückgabe.
Selbstaufruf: Pfeil schlägt zurück auf eigene Lifeline.
Bedingungen / Schleifen als loop/alt/opt-Block.
Häufiger IHK-Stil: Vorgegebene Aktoren App, :WebService, Database. Ergänzen: GET-Anfrage → Cache-Check → ggf. DB-Aufruf → Antwort mit Status 200.
1.5.5 Zustandsdiagramm
Modelliert Lebenszyklus eines Objekts: Zustände (abgerundetes Rechteck), Übergänge mit Auslöser/Bedingung/Aktion.
Beispiel Auslastung:
Start ●→[ frei ] —"Fahrgast steigt ein"→ [ teilbesetzt ]   [ teilbesetzt ] —"95% Kapazität"→ [ vollbesetzt ]   [ vollbesetzt ] —"Fahrgast steigt aus"→ [ teilbesetzt ]   [ vollbesetzt ] —"Endhaltestelle"→ ⏺
Übergangs-Notation: Auslöser [Bedingung] / Aktion.
1.6 ER-Modell und Normalisierung
Notation (Chen vs. Krähenfuß)
Chen: Entität (Rechteck), Attribut (Ellipse), Beziehung (Raute) mit Kardinalitäten 1:1, 1:n, n:m.
Krähenfuß (häufig in IHK):

——○

Regeln:
Schlüsselattribute unterstreichen (Primärschlüssel).
n:m wird beim Mapping in Tabellen zur Zwischentabelle mit zwei Fremdschlüsseln.
Beziehung kann selbst Attribute haben (z. B. „beantwortet" mit Zeitpunkt) — wird zur Beziehungstabelle.

Form
Bedingung

Anomalien (typische IHK-Frage):
Einfügeanomalie: kann neuen Datensatz nicht einfügen, ohne unzusammenhängende Daten mitzugeben.
Änderungsanomalie: Wert ist redundant gespeichert; Änderung muss an mehreren Stellen erfolgen.
Löschanomalie: beim Löschen geht ungewollt Information verloren.
1.7 Datenbank-Architektur & Tabellen
Vom ER-Modell in Tabellen:
Jede Entität → eine Tabelle. Primärschlüssel unterstrichen.
1:1-Beziehung → Fremdschlüssel in eine der Tabellen.
1:n-Beziehung → Fremdschlüssel auf der n-Seite.
n:m-Beziehung → Zwischentabelle mit beiden Fremdschlüsseln (zusammen oft Primärschlüssel).
Mehrwertige Attribute → eigene Tabelle.

1.9 Mockup · UI/UX
3 typische Mängel (Punkt für Punkt nennen, je 2 P):
Kontrast/Lesbarkeit: zu kleine Schrift, geringer Kontrast, Farbblindheit nicht beachtet.
Konsistenz: Buttons unterschiedlich gestaltet, Navigation springt.
Affordance: Klickbares sieht nicht klickbar aus, kein Hover.
Feedback: Nutzer sieht nicht, dass Aktion ausgeführt wurde.
Fehlermeldungen: unklar, nicht in Nähe des Eingabefelds.
Effizienz: zu viele Klicks für Hauptaktion.
Barrierefreiheit: Tastaturbedienung fehlt, kein Alt-Text.
Mobile / Responsive: Layout zerbricht.
Nielsen-Heuristiken (10) — Stichworte zum Auswendiglernen: Sichtbarkeit, Realitätsbezug, Nutzerkontrolle, Konsistenz, Fehlervermeidung, Wiedererkennen statt Erinnern, Flexibilität, Ästhetik/Minimalismus, Hilfe bei Fehlern, Hilfe & Doku.
Verbessertes Mockup zeichnen: Header (Logo + Titel), Navigation, Hauptbereich klar strukturiert, eindeutiger CTA, Footer. Auf wireframe-Niveau zeichnen — keine Farben nötig.

1.13 Qualitätssichernde Maßnahmen

Bubble Sort in Pseudocode (kann immer abgefragt werden!):
function bubbleSort(arr: Element[], vergleiche: Function) : void {    n = arr.size()    for i = 0 to n - 1 {        for j = 0 to n - i - 2 {            if (vergleiche(arr[j], arr[j+1]) > 0) {                tmp     = arr[j]                arr[j]  = arr[j+1]                arr[j+1] = tmp            }        }    }}
Insertion Sort:
function insertionSort(arr: Element[], vergleiche: Function) : void {    for i = 1 to arr.size() - 1 {        key = arr[i]        j   = i - 1        while (j >= 0 AND vergleiche(arr[j], key) > 0) {            arr[j+1] = arr[j]            j        = j - 1        }        arr[j+1] = key    }}
Tipp aus IHK 2024 Sommer Teil 2 Aufgabe 2a: Wenn eine Vergleichsfunktion als Function-Objekt übergeben wird (Strategy Pattern), nicht direkt < benutzen, sondern vergleiche(a, b) > 0-Bedingung verwenden!
Binäre Suche
function binaereSuche(arr: Integer[], gesucht: Integer) : Integer {    links  = 0    rechts = arr.size() - 1    while (links <= rechts) {        mitte = (links + rechts) / 2        if (arr[mitte] == gesucht) { return mitte }        if (arr[mitte] < gesucht)  { links = mitte + 1 }        else                       { rechts = mitte - 1 }    }    return -1}
Voraussetzung: sortierter Array. Komplexität: O(log n).
Beispielaufgabe (IHK-Stil) — Zähle Elemente, die Bedingung erfüllen
function notierungPlus(kurse: Tageskurs[]) : Integer {    counter : Integer = 0    for each kurs in kurse {        if (kurs.getAktienVeraenderung() > kurs.getDaxVeraenderung()) {            counter = counter + 1        }    }    return counter}
Suche kleinstes Element (typische Variante)
function findeMin(arr: Integer[]) : Integer {    if (arr.size() == 0) { return -1 }      // leeres Array abfangen!    min : Integer = arr[0]                  // Wichtiger Bug-Fix-Hinweis: Init!    for i = 1 to arr.size() - 1 {           // ab 1 starten, NICHT ab 0        if (arr[i] < min) {            min = arr[i]        }    }    return min}
IHK 2025/26 Winter Aufgabe 3b: Solche Aufgaben fragen oft nach semantischen Fehlern. Häufige Bugs:1) Initialisierung min = 0 (sollte arr[0] sein, sonst werden alle positiven Werte falsch).2) Schleife läuft i = 0 statt i = 1 (vergleicht arr[0] mit sich selbst – ineffizient, aber kein Crash).3) Falsche Vergleichsrichtung (> statt <).4) Off-by-one (i <= arr.size() statt < arr.size() → IndexOutOfBounds).

3.15 EZB · Geldpolitik · Inflation
EZB = Europäische Zentralbank, Sitz Frankfurt. Ziel: Preisstabilität (Inflationsziel ~2 %).
Leitzinsen (Hauptrefinanzierungssatz, Einlagezins): steigen → Kreditkosten steigen → Konsum/Invest. sinken → Inflation sinkt.
Inflation: allgemeiner Preisanstieg. Gemessen an Verbraucherpreisindex.
Deflation: allgemeiner Preisrückgang.
Stagflation: stagnierende Wirtschaft + Inflation.
Konjunkturphasen: Aufschwung → Hochkonjunktur (Boom) → Abschwung (Rezession) → Tiefphase (Depression).
Konjunkturpolitik:
Antizyklisch: Staat investiert in Tiefphase, spart in Hochphase.
Expansive Geldpolitik: EZB senkt Zinsen.
Restriktive Geldpolitik: EZB hebt Zinsen.

Prüfungstag — Last-Minute Strategie
Am Vorabend
8 h Schlaf (echt!). Die letzte halbe Stunde Lernen ist immer schlechter als ausgeschlafen sein.
Vorbereitung packen: 2 Kugelschreiber blau + Reserve, Bleistift + Radierer, nicht-programmierbarer Taschenrechner, Personalausweis, Einladung, Wasserflasche, Traubenzucker.
Cheatsheets (Kapitel 6) noch einmal überfliegen — nicht neu lernen!
Am Prüfungstag morgens (für jeden Teil)
30 min vorher im Prüfungsraum.
Zur Tagesform passendes leichtes Frühstück + Kaffee/Wasser.
Ankommen, hinsetzen, 3× tief atmen (4-7-8: 4 ein, 7 halten, 8 aus).
Nach Aufgabenausgabe: Erst Deckblatt ausfüllen, dann alle Aufgaben in Ruhe komplett durchlesen, bevor du etwas schreibst.
In jeder Klausur
Zeitstrategie
90-min-Klausur (Teil 1, Teil 2): 4 Aufgaben → Richtwert 20 min/Aufgabe, 10 min Reserve am Ende.
60-min-Klausur (WiSo): 30 Aufgaben → 2 min/Aufgabe, schwierige zurückstellen.
Punkte-Effizienz
Punkte ≈ Anzahl der erwarteten Aspekte. „Beschreiben Sie 4 Vorteile (8 Punkte)" → mindestens 4 nennen, jeden mit kurzer Begründung.
Anzahl beachten: „2 Aspekte" = nur 2 werden bewertet. Weniger = unvollständig, mehr ≠ besser (nur die ersten zählen).
Stichworte erlaubt (außer: ganzer Satz/Brief gefordert).
Sauber & lesbar. Unleserliches = falsch.
Bei UML/ER-Modellen: leicht mit Bleistift vorzeichnen, dann Kugelschreiber.
Bei Blackouts
Nicht in Panik geraten.
Aufgabe markieren, nächste machen.
Später wiederkommen — oft fällt es einem dann ein.
Rechenaufgaben
Lösungsweg immer kurz hinschreiben (Teilpunkte!).
Mit gerundetem Zwischenergebnis weiterrechnen, wenn die Aufgabe das vorgibt.
Einheiten dranschreiben.
SQL-Aufgaben
Tabellennamen 1:1 aus Aufgabe übernehmen.
Aliase verwenden (AS K für Kürze) — und in JOIN ... ON K.id = ... nutzen.
Prüfen: Ist GROUP BY vollständig? Müssen alle nicht-aggregierten SELECT-Spalten dort stehen!
Bei „mindestens 3" → HAVING ... >= 3.
Bei „absteigend nach X" → ORDER BY X DESC.
Spaltennamen wie verlangt (Aliase setzen mit AS).
UML-Aufgaben
Erst Konzept: Wer sind die Akteure / Klassen / Zustände? Aufschreiben.
Dann zeichnen.
Multiplizitäten und Sichtbarkeiten immer setzen.
Methodensignatur komplett: `+ name(parameter: Typ): Rückgabetyp`.
Pseudocode
Methodenkopf exakt wie vorgegeben übernehmen.
Variablen oben deklarieren + initialisieren.
Klammern, sauber einrücken.
return nicht vergessen.
Edge-Cases (leere Liste, null) andeuten — gibt oft Bonuspunkte.
WiSo-spezifisch
Aufgaben mit „zwei zutreffende Aussagen" → beide ankreuzen, sonst null Punkte!
Bei Unsicherheit: Ausschlussverfahren (was kann definitiv nicht sein?).
Vertraue deinem ersten Eindruck — Forscher zeigen, dass nachträgliche Korrekturen meist verschlechtern.
Du hast 60 min für 30 Aufgaben → wenn du nach 30 min bei Aufgabe 15 bist, ist das Tempo gut.
Nach jeder Klausur
Nicht mit anderen vergleichen — kostet nur Nerven.
Zwischen den Teilen: kurz Luft holen, etwas essen/trinken, nicht ins Lernheft.
Bei Pannen: Beste Strategie für den nächsten Teil ist „abhaken".
Mentale Tricks
Box-Atmung (4-4-4-4) bei Stress.
Vor Beginn: Vorstellen, wie du die Prüfung ruhig durchgehst.
Selbstgespräch: „Ich kenne den Stoff. Ich gehe Schritt für Schritt durch."
Was du NICHT machen solltest
Am Prüfungstag morgens panisch neuen Stoff lernen.
Energy Drinks in Massen — Crash mitten in der Prüfung.
Mit anderen über Prüfungsfragen diskutieren bevor alle Teile vorbei sind (führt zu Verunsicherung).
